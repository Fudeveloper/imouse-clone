## 公开确认的信息

### 产品定位

iMouse 官方首页明确说明：

- 产品基于 `iMouse 虚拟鼠键` 硬件，需要购买硬件才能实现鼠标和键盘操作。
- 使用 AirPlay 镜像做屏幕传输，手机端无需安装 App，主打 iOS 无越狱控制。
- 产品由 `内核服务端` 和 `控制台端` 构成。控制台是基于内核服务端 API 实现，用户也可以基于 API 自研控制台。
- API 支持 HTTP 或 WebSocket 调用。
- 图像能力包含 OpenCV 找图和百度飞桨 OCR。
- 官方定位是 iOS 自动化测试、批量测试和授权设备批量操作。

来源：

- https://www.imouse.cc/
- https://www.iosautot.com/

### XP 版相对旧版的关键升级

官方 XP 版帮助文档把重点放在这些能力：

- Windows 10 或更高版本，建议 8GB 内存、双核以上 CPU、优先硬件加速、有线网络。
- 所有窗口可分离并独立控制。
- 搭配 4.4 固件和有线投屏后，投屏后自动绑定硬件。
- 投屏连接从 6 到 7 秒降到约 1 秒。
- 单一投屏服务，资源占用更低，支持硬件解码。
- 画质升级，支持全高清显示。
- 自适应设备分辨率，例如 iPhone 6s 为 750x1334，iPhone 16 Pro 为 1206x2662。
- 每台设备可独立配置分辨率、刷新率、声音等参数。
- 自动投屏、重启自适应。
- H264/H265 投屏硬件解码。
- “快准狠”鼠标模式，要求 iOS 17+ 和 4.4 固件。
- 多设备音频解码、多国语言、Emoji、横屏和高分辨率支持。
- 快捷指令增强，包含压缩传输、清空相册、关机等操作。
- 设备列表和分组云端存储、子账号、局域网可见范围规则、自动更新。
- UI 自定义、控制台与画面显示分离、多进程增强刷新效率、调试工具、多点取色、请求/返回日志、自定义快捷键。

来源：

- https://www.iosautot.com/XP版帮助文档/软件简介

### XP API 与 Python 开发形态

官方 XP API 文档体现出 XP 版 API 不是简单 REST 资源风格，而是有 `fun` 功能名的统一入口形态：

- OCR 示例功能名为 `/pic/ocr`。
- 支持 GET、POST multipart、POST JSON，也说明 WebSocket 可发送同样 JSON 请求。
- OCR 返回字段包含 `text`、`centre`、`rect`、`similarity`。
- 文档还列出图色类能力：截取屏幕、普通找图、OpenCV 找图、OCR、查找文字、多点找色。
- 端口和协议形态围绕本地服务展开，典型调用目标是本机 `9911` 端口的 `/api`。

Python XP 开发文档说明：

- `imouse-py` 是面向 XP 版的客户端库。
- 必须配套 iMouse XP 专用硬件使用。
- Python 调用层包含 API 类和 helper 类。
- helper 的 console 侧覆盖 `Device`、`AirPlay`、`USB`、`Group`、`ImConfig`、`User`。
- Python 示例中直接调用 `api.mouse_click`、`api.mouse_swipe`，也能连接控制台、投屏设备、注册事件回调。
- 这说明 XP 版真正产品化的重点不是单个点击 API，而是设备、投屏、USB、分组、配置、用户权限和回调事件的整套运行时。
- 2026-06-08 复核时，官方 Python XP 页写的是 `pip install imouse-py`；同时 PyPI 可检索到 `py-imouse-xp`。后续 SDK 对接不要只按包名安装，必须先锁定来源、版本、hash、API mode（HTTP/WebSocket）和硬件实测证据，避免装到非官方或不同协议版本的包。

来源：

- https://www.iosautot.com/XP版API文档/图色相关/OCR文字识别
- https://www.iosautot.com/python-xp/
- https://doc.some3c.com/xp-api-documentation
- https://doc.some3c.com/xp-api-documentation/python-library

## 行业主流方案

### 方案 A：XCUITest / WebDriverAgent / Appium

适合正规 App 自动化测试。优点是元素级语义强、断言清晰、可维护性好；缺点是需要开发者签名、设备信任、WDA 部署，跨 App、系统 UI、灰产式批量操作场景会遇到权限和稳定性边界。这个路线适合“测试自家 App”，不适合对标 iMouse XP 的“无 App、跨界面、黑盒群控”核心卖点。

适合作为我们的辅助能力：设备信息采集、安装测试包、拉日志、专项测试，而不是主控链路。

### 方案 B：AirPlay 取画面 + USB HID 输入

iMouse XP 属于这条路线。核心是把 iPhone 当作一台可接收鼠标键盘的设备：

- AirPlay 或有线投屏负责画面。
- 专用 HID 硬件负责点击、滑动、键盘输入。
- 视觉识别负责从画面中定位目标。
- 控制台和 API 把这些能力组织成可批量调用的产品。

优势：

- 手机端无需越狱、无需安装 App。
- 能跨 App 和系统界面。
- 对业务脚本语言友好，只要能 HTTP/WebSocket 即可调用。
- 群控时可以做统一窗口、分组、同步操作。

代价：

- 必须依赖硬件、固件、线材、USB Hub、网络。
- 坐标、分辨率、横竖屏、刘海/安全区、投屏裁剪都会影响点击准确性。
- AirPlay 发现、连接、编码、解码、黑屏、延迟是大坑。
- 模板图、OCR、找色都属于黑盒视觉，脚本鲁棒性依赖资产规范。

### 方案 C：MDM / 快捷指令 / Apple Configurator

适合批量配置、安装、擦除、证书、网络、合规管理。它不是像素级控制方案，不能替代鼠标点击和视觉识别，但可以作为群控 SOP 的设备初始化层。

### 方案 D：越狱或私有 API

不建议作为主流研发路线。短期能力强，但系统版本、签名、合规和售后风险都高，也不符合 iMouse XP 官方宣称的“标准 iOS 无越狱”路径。

## 对标 XP 的合理目标架构

### 第一层：内核服务端

职责：

- 设备注册、设备状态机、设备分组。
- 硬件发现、绑定、固件版本识别。
- 投屏会话管理。
- 截图/帧流输出。
- 鼠标键盘 HID 指令下发。
- OpenCV 找图、找色、多点找色、OCR、找文字。
- HTTP 和 WebSocket API。
- 请求、响应、错误、性能指标日志。

XP 对标要点：

- API 需要兼容 `fun` 功能名入口，而不仅是当前仓库这种 `/api/click` REST 风格。
- HTTP 和 WebSocket 的协议层要统一请求/响应格式。
- 错误码、设备 ID、分组、批量调用、事件回调要从一开始设计，不要后补。

### 第二层：投屏服务

当前仓库使用 UxPlay + X11/Xvfb 的思路，更像 Linux 原型，不等同于 XP 版的 Windows 产品级投屏服务。

XP 对标要点：

- Windows 原生运行。
- 单一投屏服务管理多设备。
- 支持有线投屏优先，降低发现和无线不稳定。
- H264/H265 硬解。
- 每设备独立分辨率、刷新率、声音设置。
- 能处理横竖屏切换、高分辨率、黑屏重连。

研发建议：

- P0 先用现成 AirPlay Receiver 验证一台设备画面采集链路。
- P1 做稳定的窗口句柄/帧采集抽象，不把采集绑死到某个窗口标题。
- P2 再研究单服务多设备、硬解和有线投屏。

### 第三层：HID 硬件与固件

当前仓库实现的是 CH9329 串口 HID 协议。它能作为验证绝对鼠标、键盘注入的起点，但不能假设等于 iMouse XP 4.4 固件。

XP 对标要点：

- 自动硬件绑定需要固件、设备 ID、投屏 ID、USB 拓扑之间有可关联的信息。
- iOS 17+ 的“快准狠”模式需要实测，不应只靠 CH9329 普通绝对坐标。
- 滑动、长按、组合键、滚轮、音量键、静音等都要在真机上形成测试矩阵。
- 每台设备一套硬件，一台 PC 多设备时 USB Hub 供电和串口稳定性非常关键。

### 第四层：视觉识别与脚本运行时

必备能力：

- 截屏。
- 普通找图、OpenCV 找图。
- 找色、多点找色。
- OCR、查找文字。
- 区域裁剪。
- 调试图输出。
- 图像资产管理。
- 脚本步骤录制、回放、失败截图。

关键坑：

- 单色或低纹理模板会导致 `cv2.matchTemplate` 假阳性。
- Retina 分辨率和窗口缩放会导致坐标错位。
- OCR 首次运行要下载模型，必须有可写缓存目录。
- PaddleOCR 2.x 与 3.x 返回结构不同，代码必须兼容。

### 第五层：Python GUI 控制台

前期 Python GUI 建议用 PySide6，而不是 Tkinter：

- 多设备窗口、停靠面板、日志表格、快捷键、图像画布更成熟。
- 后续可把投屏画面和控制台拆进不同进程。
- 可以先嵌入静态截图/低帧率预览，避免一开始就被高性能视频渲染拖住。

MVP 页面：

- 设备列表：状态、iOS、型号、分辨率、硬件端口、投屏状态。
- 设备画面：截图刷新、坐标取点、点击、滑动。
- 图色工具：截模板、找图、找色、多点找色、OCR。
- 脚本面板：运行、暂停、停止、步骤日志、失败截图。
- 设置：投屏参数、硬件端口、缓存目录、API 端口。

## iMouse XP 迭代路径带来的研发启示

从官方 XP 文档看，它的迭代不是“多加几个 API”，而是围绕群控现场的痛点推进：

1. 先解决免越狱和无 App 控制：AirPlay + 硬件 HID。
2. 再解决脚本开发效率：HTTP/WebSocket API、Python SDK、OpenCV、OCR。
3. 再解决群控运维：设备列表、分组、子账号、云端同步、局域网规则。
4. 再解决性能体验：单一投屏服务、硬件解码、窗口分离、多进程显示。
5. 最后解决现场效率细节：自动绑定、1 秒投屏、快捷指令、调试工具、快捷键、Emoji、横屏、音频。

我们的研发顺序也应如此：

- 先把单设备闭环做到可验证：能看、能点、能滑、能截图、能找图。
- 再做群控：设备管理、分组、批量命令、日志、失败隔离。
- 再做性能：低延迟、硬解、多窗口、自动重连。
- 最后做体验：GUI 布局、快捷键、云同步、账号权限。

不要一开始就追“完美群控 GUI”。如果单设备点击坐标和投屏帧都不稳定，群控只是把问题放大。
